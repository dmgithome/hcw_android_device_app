# 耗材屋安卓重构验收标准 v2（稳定版）

更新时间：2026-02-24  
说明：本文件只写“**验收标准**”，不写“当前完成度/进度结论”。进度请写入 `docs/验收记录.md`。

## 1. 验收原则（必须全部满足）

1. **1:1 复刻业务口径**：规则以“既有口径”为准，重构不能悄悄改规则。
2. **UI/UX 行为一致**：流程、反馈、信息层级、可操作性一致；允许 Android 习惯差异，但必须写入差异清单并说明影响。
3. **对外口径不变**：HTTP API / MQTT topic / 错误语义（尤其 409 并发冲突）必须保持不变。
4. **证据必填**：每条验收项必须至少有一种证据（操作步骤 + 截图/录屏/日志路径）。

## 2. 对外口径锁定清单（不可变）

### 2.1 HTTP API（路径与语义不可变）

来源：`app/src/main/java/com/hv/cabinet/data/api/CabinetApi.kt`

- `POST /api/v1/amis/login`
- `POST /api/nfc/loginByNFC`
- `GET /api/v1/amis/user_info`
- `GET /api/cabinet/getAllCabinetList`
- `GET /api/inventory/callInventory?IP=...`
- `GET /api/locations/list`
- `GET /api/locations/default`
- `POST /api/stock/getConsumeOrReturnConsumablesByBarcode`
- `POST /api/stock/createTakeAndReturnLog`

### 2.2 MQTT Topic（不可变）

来源：`app/src/main/java/com/hv/cabinet/data/mqtt/MqttManager.kt`

- `table/rfid/fast_tag/#`（RFID 标签流）
- `table/rfid/inventory_status/#`（盘点状态）
- `dk25_nfc/card/#`（刷卡消息）

### 2.3 关键字段与语义（不可变）

- 取用提交必须携带 `to_location_id`，未选择目标位置必须阻止提交。
- 归还提交每条必须携带 `expected_current_location_id`（并发校验）。
- 后端返回 409：属于“并发冲突/位置不一致”语义，前端不能简单提示“失败”，必须让用户能理解并定位冲突条目（至少提示冲突 RFID 数量，并高亮/列出）。

## 3. 状态机验收（必须覆盖异常与恢复）

### 3.1 取用/归还通用状态（来自 `InventoryFlowState`）

| 状态 | 触发条件 | 期望反馈 | 必须可恢复/可继续 |
|---|---|---|---|
| `Idle` | 页面进入/流程完成后 | 可开始、可扫码、可移除 | 是 |
| `Starting` | 点击开始盘点 | “正在启动…”提示 | 是（失败能重试） |
| `WaitingAck` | 已发送盘点命令 | “等待设备响应”提示 | 是（超时可重试） |
| `Inventorying` | 收到 start ACK | 显示盘点中 | 是（可持续扫码/放置） |
| `Submitting` | 点击提交 | 提交中提示/按钮不可重复 | 是（失败能修正后再提） |
| `Completed` | 提交成功 | 成功提示 | 是（自动回到可继续操作） |
| `Error` | 网络/超时/冲突/解析失败 | 错误提示清晰可理解 | 是（给出下一步，如重试/刷新） |

### 3.2 必须覆盖的异常路径（每条都要证据）

- **启动盘点超时**：等待设备 ACK 超时后必须提示；用户可一键重试；不会卡死。
- **断网/后端不可用**：必须提示网络问题；不允许无穷加载；恢复网络后可继续。
- **MQTT 断开/重连**：断开有提示；重连后不需要重启 App 才能继续操作（至少不影响基本流程）。
- **离开页面再回来**：状态应回到可操作状态，或给出明确提示（不能残留“不可点击”）。
- **高频 RFID 消息**：列表更新不中断操作，按钮/输入不会明显卡顿。

## 4. UI/UX 行为一致验收（逐屏对照）

> 这里的“一致”是行为一致：步骤与反馈一致。外观允许少量差异，但不能影响理解与操作。

### 4.1 登录页

- 账号登录：输入账号/密码 -> 登录 -> 成功进入主页；失败提示清楚。
- NFC 登录：页面提示“刷卡自动登录”；刷卡后自动登录；不要求用户手工输入卡号/IP。
- 配置区：API/MQTT 配置可保存；保存结果提示清楚；重启后仍生效（持久化）。

### 4.2 取用页

- 开始盘点：点击后进入等待/盘点中状态，状态提示清楚；失败能重试。
- 扫码/盘点导入：可提交项与异常项分区清楚；异常文案可不同但分类必须一致。
- 目标位置：必须“选择”，不能手填；未选择不可提交，并提示原因。
- 冲突提示：409 时提示清楚，并能定位冲突条目（至少冲突数量 + 冲突高亮）。

### 4.3 归还页

- 扫码/盘点导入：只有可归还条目进入可提交列表，其余进入异常提示。
- 提交：成功后清空列表并回到可继续操作；409 冲突提示与定位同取用。

## 5. 功能回归用例（建议每轮至少全跑一次）

> 证据要求：每条用例至少提供一种证据（截图/录屏/日志路径）。

### 登录

- **A-01 账号登录成功**：正确账号密码登录 -> 成功进入主页并拿到用户信息。
- **A-02 账号登录失败提示正确**：错误账号或密码 -> 提示清楚，不进入主页。
- **A-03 NFC 自动登录成功**：MQTT 收到刷卡消息 -> App 自动登录成功。
- **A-04 NFC 严格模式失败拦截**：严格模式下收到非法 Value -> 明确提示，不继续登录。
- **A-05 MQTT clientId 稳定**：重启 App 两次 -> clientId 不变。

### 取用

- **A-06 开始盘点成功**：点击开始盘点 -> 进入盘点中（或明确等待 ACK），可持续扫码。
- **A-07 开始盘点超时处理**：模拟无 ACK -> 超时提示 + 可重试 + 不会卡死。
- **A-08 取用扫码分类正确**：准备多种状态样本 -> 只有可取用项进入可提交列表，其余进入异常提示区。
- **A-09 取用目标位置必须选择**：不选目标位置直接提交 -> 前端阻止提交并提示原因。
- **A-10 取用提交成功**：有可提交条目 + 已选目标位置 -> 提交成功，列表清空，可继续下一次操作。
- **A-11 取用并发冲突（409）提示明确**：制造并发冲突 -> 提示清楚并能定位冲突条目。

### 归还

- **A-12 归还扫码分类正确**：准备多种状态样本 -> 只有可归还项进入可提交列表。
- **A-13 归还并发校验（409）生效**：提交前修改条目当前位置 -> 409 冲突提示清楚并可定位。
- **A-14 归还成功链路完整**：提交归还 -> 成功、列表清空、页面可继续操作、无白屏卡死。

## 6. 非功能（性能/稳定性）验收

- **高频消息可操作性**：盘点高频标签流下，按钮/输入仍可用，不出现明显卡死。
- **页面切换稳定**：登录/取用/归还来回切换不闪退、不白屏。
- **错误可恢复**：网络异常/超时/冲突后，用户有明确“下一步”可做（重试/刷新/返回）。

建议证据（可选但强烈建议）：

- 使用 `scripts/perf_framestats.sh` 采样一次，并把输出保存为证据文件（见第 8 节命名规则）。

## 7. 代码质量门禁（至少满足以下要求）

### 7.1 必跑命令（每轮至少跑一次并保存输出）

在仓库根目录执行：

```bash
./gradlew :app:compileDebugKotlin
./gradlew :app:assembleDebug :app:assembleRelease -x lint
./gradlew :app:testDebugUnitTest
```

### 7.2 禁止项（重构常见坑）

- 不把“业务规则”写在页面 UI 里（UI 只负责展示与交互）。
- 不引入“随机且不可追溯”的关键标识（例如 MQTT clientId 不能每次随机）。
- 不用“通用失败”掩盖关键错误（尤其是 409 并发冲突）。

## 8. 证据要求与命名规则（必须遵守）

### 8.1 证据类型（任选其一或组合）

- 截图（`.png`）
- 录屏（`.mp4`）
- 日志片段或命令输出（`.txt`）

### 8.2 证据文件命名（固定）

`evidence/YYYY-MM-DD_<模块>_<场景>_<pass|fail>.<png|mp4|txt>`

示例：`evidence/2026-02-24_login_nfc_auto_pass.mp4`
